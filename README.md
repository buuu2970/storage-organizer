# RecSort — 録画の整理

> 学校課題「録画の容量がいっぱいだが、どれを削除すればいいかわからないので選んでほしい」を解決する
> Windows 向けのアプリです。**ブラウザで開いて使います**（このパソコンの中だけで動く小さなサーバー + ブラウザの画面）。

PC 内のドライブを調べて、録画がどれくらい容量を使っているかを示し、**整理を考えるとよい録画を理由付きで提案** します。
録画をプレビューして「残す・保留・削除候補」を選び、最後に確認したファイルだけを Windows のごみ箱へ移します。

- 提案は決まったルール（重複・極端に短い・黒画面が多い・読み込み失敗・無音など）によるもので、AI の判定ではありません。
  動画の価値や面白さは判断しません。「不要」とは表示しません
- 自動削除・完全削除はしません。ごみ箱を空にしません
- データベースは使いません（設定・判断・保護・お気に入り・調査結果は JSON などの通常のファイル）
- 個人の録画やファイル情報を外部へ送信しません。サーバーはこのパソコンの中（127.0.0.1）だけで動き、インターネットには公開しません

バージョン: 1.0.0（統合版）。統合の経緯・採用したコード・テスト結果は `INTEGRATION_NOTES.md` を参照してください。
学校発表用の資料（設計判断・想定質問・変更履歴）は `docs/presentation/` にあります。

## 起動

```
pip install -r requirements.txt
python main.py
```

既定のブラウザで RecSort の画面（`http://127.0.0.1:8765/` など）が開きます。黒いウィンドウ（サーバー）を閉じるか Ctrl+C で終了します。
Windows 10/11、Python 3.12 以上（3.14 で確認）。FFmpeg は任意です（下記）。

| 起動方法 | 内容 |
|---|---|
| `python main.py` | **ブラウザ版（標準）**。起動すると自動で調査を始めます（設定で変更可） |
| `python main.py --no-browser` | ブラウザを自動で開かない（表示された URL を自分で開く） |
| `python main.py --desktop` | デスクトップ版（PySide6）。画面と操作の手本として残しています |

ブラウザ版とデスクトップ版は同じ保存データを使います。記録が食い違わないよう、同時には起動できません。

### ブラウザ版のしくみと安全対策

- 画面は `storage_organizer/web_ui/`、サーバーは `storage_organizer/webapp.py`（Python の標準ライブラリだけ）。
  調査・整理候補・保存・ごみ箱への移動は、デスクトップ版と同じ処理をそのまま使います
- サーバーは 127.0.0.1 だけで待ち受けます（ほかのパソコンからは開けません）
- 起動ごとに作る合言葉（トークン）がない要求は断ります。ほかのサイトのページから、こっそり操作されないようにするためです
  （Host ヘッダーも確認します）
- 再生できるのは、調査で登録した録画だけです（任意のファイルは読ませません）。ブラウザが再生できない形式（.ts など）は
  「保存場所を開く」でエクスプローラーから確認します
- ごみ箱への移動は、最終確認と確認ダイアログで承認したときだけです（承認のない要求はサーバーが断ります）

## 画面と使い方

| 画面 | できること |
|---|---|
| ホーム | 録画の件数・合計容量、整理候補の件数と容量、重複を整理した場合の削減見込み、選んだ削除候補の合計、ドライブの空き容量。「どこから確認するとよいか」のおすすめ |
| ファイル一覧 | 録画の一覧（名前・形式・容量・更新日時・判断・お気に入り・保護・整理候補の理由・保存場所）。検索、判断での絞り込み、容量順・更新日時順・名前順などの並べ替え。選ぶとプレビュー（再生・停止・シーク・再生時間）とファイル情報・理由を表示 |
| 整理のおすすめ | 完全重複・類似録画・確認が必要な録画を理由付きで表示。比較して残す1本を選べる。目標容量（今より○GB 空けたい）からの提案もできる。チェックした録画を「削除候補に追加」 |
| 削除候補 | 削除候補にした録画の一覧 → 最終確認（名前・保存場所・件数・容量）→ ごみ箱へ移動 → 結果（移動した・安全確認で止めた・失敗を分けて表示） |
| 設定 | FFmpeg の場所、自動調査、調査する場所・除外する場所、キャッシュ、保護記録の初期化 |

ごみ箱へ移しただけでは空き容量は増えません。ごみ箱を空にすると増えます（画面にも表示します）。

### 判断の用語

| 用語 | 意味 |
|---|---|
| 未判断 | まだ判断していません |
| 残す | この録画は残しておきます |
| 保留 | あとで確認して決めます |
| 削除候補 | ごみ箱に移動する候補に追加します。まだ削除されません |
| 保護中 | 保護を解除するまでごみ箱へ移動できません |
| ★ お気に入り | 整理のおすすめから外します（「残す」に近い扱い）。保護とは別の状態で、外すと対象に戻ります |

判断・保護・お気に入りはアプリ全体で共通です。

## 調査（全ドライブの自動スキャン）

- ビデオ・デスクトップ・ダウンロードなどのフォルダ（Windows の既知フォルダ API で実際の場所を取得）を先に調べ、
  その後に内蔵ドライブ全体を調べます。起動時に自動で更新します（設定で変更可）
- 外付け・ネットワーク・リムーバブルドライブは自動では調べません（設定の「追加で調べる場所」で追加できます）
- Windows・Program Files・ProgramData・AppData・キャッシュなどのシステム・アプリの領域は除外します（既知フォルダ API で判定）
- リンク・ジャンクションはたどりません（循環・二重集計を防ぐ）。アクセスできない場所はスキップして件数を表示します
- オンライン専用（クラウドにだけある）ファイルは読み込みません（勝手にダウンロードしない）
- 調査は別スレッドで行い、一時停止・再開・キャンセルできます。全体の件数が分かるまで進み具合の割合は表示しません
- 一覧に登録するのは録画（動画ファイル）だけです。ほかの種類は「容量の内訳」の集計にだけ使います
- 変更のないファイルは、前回の解析結果を使い、再解析しません

## 整理候補のルール

| 理由 | 判定 | 扱い |
|---|---|---|
| 完全重複 | サイズで絞り、ファイル全体の SHA-256 で一致を確認（名前だけでは判定しない） | 各グループで必ず1本を残す（保護 → お気に入り → 最も古いもの）。提案どおり選択済み |
| 類似録画 | 長さがほぼ同じで、代表 12 場面の大半が一致 | 同じ内容とは限らないため、比較して残す1本を確定するまで選べない |
| 極端に短い | 再生時間 3 秒未満 | 要確認（未選択） |
| 黒画面が多い | 確認した 3 場面がほぼ真っ暗 | 要確認（未選択） |
| 読み込み失敗 / 再生できない可能性 | 動画として読み込めない・0 バイト・索引情報がない | 破損とは断定しない。要確認（未選択） |
| 音声がほぼ無音 | 音声トラックがあり、確認した 3 か所（各 10 秒）の最大音量がすべて -50 dB 未満 | 要確認（未選択）。測れない区間があれば判定しない |
| 大容量 | 100MB 以上（一覧に表示） | **これだけでは削除をおすすめしない**。目標容量を指定して足りないときだけ「要確認」に加える |

- 保護中・お気に入り・「残す」・保留・オンライン専用の録画は、おすすめに含めません
- 目標を満たすために基準を緩めたり、根拠のない候補を足したりしません。足りなければ不足分を表示します
- 同じファイル（別の表記・ハードリンク）を二重に数えません。別のドライブの録画は、目的のドライブの解放見込みに含めません

## ごみ箱への移動（安全対策）

- 移動は「削除候補」画面の最終確認と、確認ダイアログでの承認の後だけ行います
- 移動の直前に、ファイルの存在・スキャン後の変更（サイズ・更新日時）・保護・残す側の実在を確認し、問題があれば移動しません
- Windows の `IFileOperation`（pywin32）を使い、次の場合は移動しません（フェイルクローズ）
  - 固定ドライブ以外（USB・ネットワークなど）、ごみ箱が使えない、「ごみ箱に移動しない」設定、ごみ箱の最大サイズ超過
  - 削除直前の通知（`PreDeleteItem`）に「ごみ箱へ移す」指定がない（Windows が完全削除しようとしている）→ その場で中止
  - 移動後に、ごみ箱内の項目が作られたことを確認できない
- 完全削除・別の削除方法への切り替えは一切しません。結果は記録（`trash_log.jsonl`）し、移動・スキップ・失敗を分けて表示します
- 元に戻すときは、Windows のごみ箱から復元してください

## FFmpeg（任意）

録画の長さ・黒画面・無音・類似録画・サムネイルの判定に使います。アプリは **自動でインストールしません**。
設定で指定したフォルダ → PATH → WinGet でインストールした場所（`%LOCALAPPDATA%\Microsoft\WinGet\Links`・`Packages`）の順に探します。

```
winget install Gyan.FFmpeg
```

FFmpeg がなくても、録画の一覧・容量の集計・完全重複の検出・ごみ箱への移動は使えます。

## データの保存（データベース不使用）

保存先: `%LOCALAPPDATA%\RecSortV1`（以前の版の `RecSortAI`・`RecSort` とは別。以前のデータは読み書きしません）

| 内容 | ファイル |
|---|---|
| 設定（保存形式の版 `schema_version` を含む） | settings.json |
| 判断・保護・お気に入り・確認日時（パスごと） | user_state.json |
| 調査場所・スキップ・容量の集計・類似グループ | scan_state.json |
| 調査場所ごとの録画の一覧 | inventory/*.json.gz |
| 解析結果のキャッシュ（パス・サイズ・更新日時で照合） | analysis.jsonl（追記のみ） |
| ごみ箱への移動の記録 | trash_log.jsonl（追記のみ） |

- 保存は「一時ファイルに書く → fsync → 読み直して内容を確認 → 直前のファイルを .bak に残して置き換える」
- 壊れたファイルは消さずに `.broken-*` へ退避し、`.bak` から復旧します。保護の記録を復旧できないときは整理操作を止めます
- 判断はまとめて1回で保存し、確認日時は終了時などにまとめて保存します（選ぶたびに全体を書き直さない）
- 新しい版のアプリで保存されたデータ（`schema_version` が新しい）は変更しません
- 二重起動を防ぐロックを取ってから保存データを読み書きします

## 開発

```
pip install -r requirements.txt pytest
python -m pytest tests          # または python -m unittest discover -s tests
python tools/recycle_bin_live_test.py   # 実機のごみ箱で、ダミーファイルの移動と復元を確認（Windows のみ）
```

テストは一時フォルダの合成ダミーファイルだけを使い、実際の録画やごみ箱は使いません（本物のごみ箱の試験は上のツールで別に行います）。
機械学習（ジャンル分類・厳選 AI・初期学習）は今の版には含めていません。以前の実装は元のブランチに残っています。
