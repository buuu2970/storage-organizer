## 第1部：最重要10問

### Q1. このアプリは、課題のどんな問題を解決するのですか？
- **短い回答**：録画で容量がいっぱいのときに、「どれを消せばよいか」を理由付きで示すアプリです。重複・極端に短い・黒画面・読み込めない・無音といった録画を候補として出します。消すかどうかは本人が確認して決め、決めたものだけをごみ箱へ移します。
- **詳しい回答**：
  - 処理の流れは「全ドライブを調査 → 容量を表示 → 理由付きの候補 → プレビューで確認 → 残す／保留／削除候補を選ぶ → 最終確認 → Windows のごみ箱へ」です。
  - アプリは動画の価値を判断せず、客観的な条件だけで候補を出します。
- **根拠**：README.md、organizer.py（HomePage・PlanPage・CandidatesPage）、課題文は 83433b1:README.md と 0b69654 のコミット本文
- **追加で聞かれそうな質問**：「アプリが自動で選んで消せばよいのでは？」→ Q2
- **確かさ**：【確認済み】

### Q5. 重複はどうやって見つけていますか？
- **短い回答**：ファイル名ではなく中身で判定しています。まずサイズが同じものに絞り、ファイル全体から SHA-256 という指紋を計算して、一致したものを重複にしています。必ず1本は残します。
- **詳しい回答**：
  - 指紋を計算するのは、サイズが同じファイルがあるものだけです（`find_exact_duplicates`）。計算の前後でファイルが変わっていれば、結果を使いません。
  - ハードリンクや表記違いの同じファイルは、重複に数えません（`file_identity`）。
  - 残す1本は「保護 → お気に入り → 最も古いもの」の順で決めます（`keep_for_duplicates`・`plan_recordings`）。
  - 移動の直前にも、残す側が存在するか確認します（trash._keeper_ok）。
- **根拠**：candidates.py、trash.py、test_integration.py（`test_duplicate_always_keeps_one`）
- **追加で聞かれそうな質問**：「最も古いものを残すのはなぜ？」→ 理由は文書にありません【不明】。
- **確かさ**：【確認済み】

### 設計判断

#### Q19. JSON はどうやって壊れないようにしていますか？
- **短い回答**：一時ファイルに書く → 読み直して確認 → 前のファイルをバックアップに残して置き換える、という順で保存しています。壊れていたら、バックアップから戻します。
- **詳しい回答**：
  - `_write_tmp` で書き込み、fsync（ディスクへ確実に書き出す命令）を行い、読み直して比較します。
